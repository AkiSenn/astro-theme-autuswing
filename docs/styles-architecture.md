# 样式架构整理与视觉回归

## 范围与修改前审计

起点为 `f111e47`。本轮只整理样式和建立自动视觉基准，不修改文章、路由、SEO、搜索、评论、转场行为或部署配置。源码审计记录见 `docs/evidence/styles/audit-before.json`，包含五份原始文件的 SHA-256、规则与声明计数。

| 文件 | 原始行数 | 职责与发现 |
| --- | ---: | --- |
| legacy.css | 1945 | 文档、导航、文章、弹窗、配置和可选功能混合；同一组件多次扩展；保留有用途的旧文章代码样式 |
| astro.css | 57 | Shiki、行号、数学溢出与目录深度，属于渲染适配，不应误删 |

静态审计发现 184 处相同选择器、相同条件下重复声明同一属性的候选项。这不是可直接删除的数量：仍须考虑简写/长写关系、状态选择器、媒体条件、打印和可选配置。

### 分类决定

- **归并**：根颜色、字体、圆角和动效变量的多次定义；卡片间距、文章字号、页脚和工具栏的被覆盖声明。
- **清理**：确认无组件/脚本/文章调用的选择器、被后续同条件规则覆盖的初始值；逐项在结果中登记。
- **保留**：Shiki 双主题、代码行号、MathJax 显示公式容器、可选评论/计数器、无 JavaScript 目录、打印与高对比模式。
- **隔离审查**：`figure.highlight` / `.hljs` 属于旧 HTML 代码高亮兼容。当前 Markdown 使用 Shiki，但原生 HTML 仍能进入渲染器，不能仅因当前三篇文章未命中就删除其表现能力。
- **保留现状**：760px / 450px 的残留媒体条件中，部分搜索、页脚和归档行为仍有效；本轮不强行改断点造成隐性设计变化。

## 执行顺序

1. CSS 零修改时，构建并建立 Edge / WebKit 的修改前截图；固定日期、外观、视口、DPR，并等待字体与图片。人工查看各布局的代表图。
2. 收拢最终生效的设计变量。构建、检查、逐像素比较。
3. 按布局、导航、卡片、文章、普通页面、弹窗等职责整理，清理可证明的覆盖与失效规则。每批构建和截图比较；失败即停下修复。
4. 完成两引擎截图与既有功能测试，记录未覆盖项。

## 视觉基准约定

- `playwright.styles.config.ts` 单独运行，不覆盖既有功能测试配置。
- `tests/styles/baseline.spec.ts`，基准位于 `tests/styles/snapshots/{projectName}`。
- Windows Edge 和 Windows Playwright WebKit 分别保存基准，不能将它们当作 Linux Chromium、Safari 真机或 Firefox 的验证。
- DPR 1，中文语言与固定时区，冻结 Date 而不冻结交互计时；减少动画模式用于稳定静态截图。真实动效由既有 motion 测试另验。
- 320、375、390、430、768、820、1024、1180、1366、1440、1920、2560 宽度；719/720、999/1000、1279/1280、1439/1440 的边界。
- 首页/文章深浅色、文章全文、归档/标签/友链/关于/公式、目录开关、搜索、灯箱、键盘焦点、打印与强制颜色。
- 普通比较禁止自动更新基准。PNG 使用 0.1 的逐像素色差阈值（Playwright 默认为 0.2），差异像素预算为零；另为每张图保存组件边界、字体、颜色、间距等精确 JSON 快照，避免图像采样容差掩盖 CSS 数值改变。`--update-snapshots=all` 只用于确认后的基准创建/设计变更，不能用来掩盖 CSS 整理回归。

### 基准稳定性修正

变量整理后的第一次比较为 50/51 通过。失败区域仅为手机搜索弹窗背景中的小头像（271 像素）。将五份原 CSS 和布局导入恢复后，同一场景连续三次运行有一次仍失败，排除了变量整理引起的样式差异；诊断图与原 CSS 重现报告保存在 evidence 中。

在原 CSS 下重新生成搜索场景基准：仅对**搜索弹窗背后的导航头像**加灰色遮罩。首页、文章、各尺寸及目录等普通截图的头像仍不遮罩。遮罩是测试覆盖例外，不能据搜索弹窗截图判断背景头像的像素表现。

另发现 WebKit 在弹窗关闭后，静止鼠标可能保留之前按钮的 hover 状态。拍摄前统一将鼠标移到 (0, 0)，焦点按钮仍保留键盘 focus-visible。外观改为每页单一初始化脚本，通过测试 URL 参数读取目标模式，避免多个初始化脚本的执行顺序不确定。这些修正均在原 CSS 下重建对应基准，随后重新应用整理后的 CSS 比较。

最初逐像素色差阈值为 0，随后发现缩放 PNG 的采样噪声会使相同边界内的图片文字产生误报。最终基准重新在原 CSS 下建立，采用上面的 0.1 图像色差阈值和精确 CSS/几何快照双重检查。JSON 按组件与内容种类取样（最多六个，更多时取首尾），不重复保存全部 Shiki/KaTeX 子 span。自动截图不是数学意义上每个像素完全相同的证明。

运行入口：`npm run verify:styles` 会顺序执行 check、build 和两引擎比较；`npm run test:styles` 比较已构建的 dist。可加 `-- --project=edge-windows` 做批次检查。Windows 基准不跨操作系统混用；同一输出目录的浏览器任务必须串行运行。

## 后续 CI/CD 的边界

当前源码与交付文档记录了静态输出、Node 本地预览及曾准备的宝塔 Nginx 适配。本轮不据此新增或启用任何服务器，也不将 Nginx 作为通用 CI 的依赖。

后续 CI 可以按 `npm ci → check → test → build → verify → 浏览器功能/视觉比较 → 上传 dist 与测试报告` 组织。视觉任务须固定操作系统、浏览器和字体；现有 Windows 基准不能直接搬到 Linux 后自动重录。发布步骤应在重新确认实际托管目标、认证方式和回滚约定后单独设计，当前不配置自动部署。
