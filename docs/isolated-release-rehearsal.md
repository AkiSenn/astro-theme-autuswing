# 隔离 Nginx 发布与回滚演练（2026-10-18）

## 实际范围与结论

按现有 `deployment/release-runbook.md`，使用 **Windows Nginx 1.30.6** 和仅绑定 `127.0.0.1` 的独立端口实际演练。没有 SSH、生产服务器、DNS、ESA 控制台或正式部署操作。只新增实验脚本与审计证据；产品、文章、URL、SEO 和生产配置未改动。

**两次完整演练均完成 A → B → A。** 最终脚本的结果见 `docs/evidence/linebox-deploy-drill/deployment-report.json`；原始目录 `.local-tools/release-drill-20261018-final/` 保留上传副本、生成配置、日志与私有校验元数据。Nginx 已正常关闭。

健康失败是**明确的测试故障注入**，不是发现真实 B 页面故障。此次验证了演练脚本收到健康失败后的回滚路径，不代表宝塔已有自动回滚功能。

测试用版本头只在本地生成配置中存在。正式模板没有改变。演练是 Windows 的“原子配置指针 + 校验 + reload”；**没有据此声称验证了 Linux 的 symlink 原子交换、目录权限、真实上传协议、宝塔配置合并或公网缓存切换**。

### 本地重跑

```powershell
node scripts/experiments/release-drill.mjs .local-tools/release-drill-new-run
```

输出目录必须位于本项目 `.local-tools/` 且尚不存在。脚本只绑定回环接口；`DRILL_BASE_RELEASE`、`DRILL_NEXT_RELEASE`、`DRILL_HISTORICAL_SITE`、`DRILL_HISTORICAL_MANIFEST`、`DRILL_NGINX`、`DRILL_MIME_TYPES` 可指定其他本地已封存输入。保留完整候选和 READY，而非仅保留某次 dist；脚本拒绝不合格候选。只停止它自己前缀下的 Nginx。

## ESA 缓存配置所需条件审计

**没有读取真实 ESA 规则，以下是待对照真实规则的验收条件，不是已配置结论。** 本地 HTTP 检查只能证明隔离 Nginx 的行为。

| 路径/对象                                | 必须核对的 ESA 条件                                                                                                         |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| HTML、`/`、目录页                        | 初次切换建议不缓存；否则及时重验证，不以全站一年缓存覆盖源站。发布/回滚清除旧 HTML，核对斜杠、index.html 等实际缓存键       |
| `/sw.js`                                 | 高优先级绕过缓存和内容改写，及时取新版本；不能被全站静态资源规则覆盖                                                        |
| `/offline.html` 与 `?v=<sha>`            | 及时重验证、禁止改写；保留版本查询参数作为缓存键或直接绕过。忽略查询参数可能把旧离线壳给新 Worker，SHA 校验会拒绝它         |
| manifest、search、robots、Feed、Sitemap  | 及时重验证/切换时定向清理，不能长期固定旧版本或把预览 noindex 带入正式交付                                                  |
| `/_astro/`、哈希 PWA 图标、版本化 vendor | 一年 immutable；不改同路径字节；回滚后依然保留新旧资源；字体 CORS 不丢失                                                    |
| 原路径图片                               | 当前模板为一天；保留版本查询参数。ESA 图片自动转码/压缩若改变既定交付字节需另行评审，不能忽略产物哈希不匹配                 |
| 压缩与改写                               | 允许有正确 `Vary: Accept-Encoding` 的传输压缩；解压后应等于产物 SHA。HTML/JS/CSS 自动精简、注入、重写需要关闭或另行设计门禁 |
| 404 与旧 301                             | 404 保留真实状态、no-store/noindex；不以 SPA 200 兜底。301 目标及查询参数正确，核对旧重定向缓存                             |
| 规则优先级                               | 导出真实路径匹配、缓存键、TTL、绕过/覆盖源站响应头的优先级，证明宽泛规则不会盖过以上特例；分别检验源站和实际 ESA 节点       |

切换时只定向清理 HTML、Worker、离线壳、清单和索引等可变资源；不清空不可变资源池。保留周期需覆盖回滚窗口及仍可能存在的旧 HTML/Worker/浏览器缓存，不在观察期内立即删除历史版本。ESA 若返回旧正文但 canonical 相同，现有 HTTP 字节哈希检查仍应失败。

## 未关闭的风险与正式发布前人工步骤

1. **Firefox 两项几何验收仍阻断**：见 `firefox-linebox-investigation.md`。独立字体控制不是完整网站新参考，未以容差或跳过处理。
2. **WebKit 偶发原生转场风险未关闭**：此前事件计数预期 3、实际 2，旧/新产物均曾间歇出现；本轮没有修改转场或重跑该专题。后续须稳定复现并区分事件观测缺陷/实际中断，单次通过不能关闭风险。
3. 备份**当前线上** Hexo 文件、宝塔 Nginx/重写/SSL 与 ESA 规则，记录可恢复路径；本地旧审计快照不能代替线上备份。
4. 在获授权的独立 Linux/宝塔测试位置验证目录权限、真正上传后 SHA/完整文件集、symlink 或选定切换机制、nginx -t/reload 与真实回滚；元数据须在公网根以外。
5. 对实际 ESA 规则逐项导出核对，验证源站和公网的解压后 SHA、缓存键/查询参数、压缩、404/301、刷新失效和回滚；本地演练没有覆盖真实 ESA。
6. 补验 HTTPS/TLS、真实设备的安装图标/PWA、旧 Hexo Worker 已有用户的升级与回退。此次演练没有替代跨版本多标签页与系统安装 UI 验收。
7. 最终封存经过完整审核的候选和验收证据，确认草稿不发布、评论保持关闭，再取得明确正式切换授权。发布时复用这份候选，失败立即停止；不从源码重新构建所谓回滚版。

本轮结果为**隔离部署/回滚机制验证完成**；正式发布仍未获验收放行，也未执行。
