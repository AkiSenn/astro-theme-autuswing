# 第五阶段：本地验收与宝塔 Nginx 交付准备

2026-10-16，独立工程 `E:/autuswing-astro`。本轮按用户确认的范围，只做本地验收，不做线上预览、上传或正式切换。akisenn.com 的目标环境是宝塔 Nginx；Workers 属于另一个独立站点 516700.xyz。

本地 Nginx 预览：**http://127.0.0.1:8788/**。辅助 Node 预览为 http://127.0.0.1:4322/ 。默认构建保留 noindex，真实评论、统计保持关闭。

## 本轮实现

- 增加独立 Nginx 配置模板与生成脚本，使用现有历史路由清单生成21条301，保留查询参数。`try_files` 支持目录与显式 `.html` 地址，未知路由返回真实404。
- 验证 HTML、Service Worker、哈希资源、版本化字体和图片的不同缓存策略，避免重复 Cache-Control；补齐 manifest MIME、gzip、ETag/304、字体 CORS 和404 no-store。
- 默认头像交给 Astro 原生图片能力生成144×144 WebP：317,783字节降至4,156字节。原始 PNG、文章图片、UI尺寸和自定义头像配置仍保留，没有新增依赖。
- Service Worker 缓存升级为 v2，只预缓存自带样式的离线页，不再额外预缓存原始大头像。激活时清理旧站点缓存，保留其他应用的缓存。
- 增加跨浏览器配置、可移植桌面阅读检查、Nginx浏览器与HTTP检查、可复现性能测量脚本。六种评论适配器继续使用受控 mock 验证；不连接真实服务。
- 修正可选 `_headers` 的通用与专用缓存规则叠加问题。该文件不供Nginx读取，不能据此宣称Workers部署已验收。
- 按用户补充要求，将配置中的“欢迎来到我的网站喵”移到关于页正文开头，移除桌面侧栏底部的重复展示；原始关于页Markdown不变，腾出的高度继续由文章目录使用。
- 按随后提出的PC宽屏要求，将文章外层上限802px改为860px、实际正文752px改为810px，字体仍18px/1.8。只在桌面文章页覆盖宽度，详见[宽屏补充](desktop-reading-wide.md)。

部署规则和复现命令见[宝塔 Nginx 交付说明](../deployment/README.md)。除用户补充的PC文章宽度调整外，没有扩大视觉重构范围；导航断点和文章数据不变。

## 性能测量

使用本地Nginx、Edge无头浏览器、Lighthouse 13.5.0，三个页面分别做3次移动端冷加载模拟和1次桌面测量，共12次。移动端为Lighthouse默认模拟网络与4倍CPU节流；桌面使用desktop预设。版本、节流、原始报告及每次结果见 [performance/summary.json](evidence/phase5/performance/summary.json)，完整LHR以gzip保存。

| 页面     | 移动端性能（三次） | 移动端LCP中位数 | 桌面性能 / LCP |
| -------- | ------------------ | --------------- | -------------- |
| 首页     | 96 / 96 / 95       | 2.855秒         | 100 / 0.603秒  |
| 普通文章 | 99 / 99 / 99       | 1.954秒         | 100 / 0.804秒  |
| 公式文章 | 92 / 92 / 92       | 3.306秒         | 100 / 0.646秒  |

三类页面的自动化无障碍与最佳实践评分均100；移动端CLS最高0.047、TBT最高36ms。公式页模拟冷加载LCP仍有优化空间，不宣称达到真实用户Core Web Vitals指标。

**SEO分数69来自有意保留的预览noindex策略，不是正式站SEO评分。** 正式抓取策略只在独立本地产物中检查：26页没有noindex、robots允许抓取、canonical与JSON-LD存在；见 [production-policy-files.json](evidence/phase5/production-policy-files.json)。自动审批拒绝了额外启动正式抓取策略本地Nginx实例，原因仅为 `blocked by policy`，因此该策略没有HTTP实测，也没有部署。当前预览Nginx的HTTP策略则已单独验证。

最初的Workers探测发生于部署环境澄清前，实例已停止，没有发布；其报告仅存入diagnostics，不能作为本轮Nginx性能基线。
