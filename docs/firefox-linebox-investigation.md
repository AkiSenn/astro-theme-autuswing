# Firefox 代码行框最小实验（2026-10-18）

## 结论与边界

**未复现原来的 23.4px ↔ 23.5px 高度切换，不能声称它已修复。** 本轮独立复现了另一个真实问题：相同计算字体、`document.fonts.status === 'loaded'`、两帧布局等待完成后，冷启动的实际字体集合和行号宽度仍可能不同。它证实采集环境存在未被此前就绪检查捕获的字体状态差异，但不足以证明原来的 0.1px 高度差全部由该原因导致。

两项站点测试的直接失败原因仍相同：Firefox 参考为 `provisional-renderer-metrics-unstable`，门禁主动拒绝它。未修改这两项断言或参考，也没有重新报告全量测试通过。

| 原站点测试                                                                                      | 当前处理                                                                  |
| ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `responsive layout geometry is unchanged after motion cleanup`                                  | 继续阻断；尚无可重复且经过认可的 Firefox 页面参考                         |
| `footer, mini rail, profile, navigation and content remain equal to their own browser baseline` | 同上；页脚位置会继承上游代码行框累计差异，不是另一个已确认的侧栏 CSS 缺陷 |

产品缺陷与环境差异的分类：**已确认独立样本存在浏览器/字体采集状态差异；尚未证明 Autuswing 本身有错误的布局规则，也尚未排除完整页面触发的 Firefox 布局缺陷。** 原始高度差是真实 DOM 几何差，不能按数值噪声豁免。未对产品做猜测性修补。

## 独立实验

入口：`scripts/experiments/linebox.html`。没有 Astro 布局、侧栏、图片、路由脚本、动画、远程字体或 Service Worker。只有 `pre > code > span.line`、CSS 行号和结尾定位标记。普通样本 160 行；另一个控制组仅提取封存文章的 160 个代码行 span，不引入文章外层结构或文章脚本。

环境：Windows `10.0.26300`、Node `22.23.2`、Playwright `1.64.1`、Firefox **157.0 / build 20261002120333**。均为 headless；浏览器来自隔离的 Playwright 安装目录，没有使用或修改用户的 Firefox 配置，也没有据此宣称普通桌面 Firefox 的字体风险已排除。独立 Marionette 配置启用系统级诊断权限，仅用于新建的临时配置目录，退出后关闭。协议依据：[Mozilla Marionette 协议](https://firefox-source-docs.mozilla.org/remote/marionette/Protocol.html)。

实际字体来自 Firefox 的 `InspectorUtils.getUsedFontFaces(Range)`；每个代码行保留字体集合及矩形。普通页面脚本无法调用这个诊断 API，因此 Playwright 补测的计算字体与 Marionette 实际字体记录分开标识，没有把候选 `font-family` 当作实际字体证明。未反向推断旧失败样本当时使用了哪一种字体。

| 实验               |   样本数 | 内容                                                                    |
| ------------------ | -------: | ----------------------------------------------------------------------- |
| 原生窗口矩阵       |      420 | DPR 1 / 1.25 / 2，各 2 次冷启动；7 种 CSS 控制、英文/中英混排、宽窄切换 |
| 独立内嵌文档       |      140 | 真正的 320 / 820 / 1440px 文档宽度；DPR 1、2 次冷启动                   |
| Playwright 补测    |      378 | 真正 320 / 820 / 320px；DPR 1 / 1.25 / 2，3 次独立进程                  |
| 历史代码 span 简化 |       40 | 仅代码内容，原样式/无行号/同字号行号/block 控制                         |
| 混合字体控制       |       40 | 行号字体及 pre/code 字体组合                                            |
| 系统字体冷启动追测 |       24 | 320px，DPR 1 / 2，各 12 个独立进程                                      |
| 固定字体文件追测   |       24 | 同上；只在实验中用显式 `@font-face` 绑定相同字体文件                    |
| **总计**           | **1066** | 每个样本首次测量和立即复测，共 **2132 份观察**                          |

普通 Firefox 窗口把 320px 请求限制到实际 **500px**；原生窗口组已按实际值记录，没有冒充 320px。独立 iframe 与 Playwright 组确认 `innerWidth === 320`。DPR 同样记录实际读数。

每份原始记录含浏览器版本/构建、配置目录、DPR、真实 viewport、字号/行高/字重/字体/kerning/渲染方式、代码块及末尾标记、每一行的 x/y/宽/高/bottom、文字矩形和实际字体。数据及字体文件 SHA256 见 `docs/evidence/linebox-deploy-drill/`。

此外，格式化后的当前实验入口补做了 2 组运行检查，结果一致，另存 `entry-smoke.json.gz`，不混入上表。Marionette 浏览器启动/诊断日志单独压缩保留，其中包含 headless 图形及系统服务警告；没有把这些警告解释为原高度问题的已确认根因。

## 实测结果

原样式的 13px × 1.8 计算行高为 **23.4px**；矩形读数如 `23.399993896484375` 和 `23.400009155273438` 随坐标浮点表示变化，160 行代码高度 **3744px**。这些读数保留原值，比较没有取整或容差。正常桌面 14px × 1.8 为 25.2px。所有首次/立即复测均相同；未出现原样式在相同条件下变为 23.5px 的事件。

实际字体主要为 `Cascadia Code Regular`；中文按字符回退到 `NSimSun`，显式 Consolas 控制组记录 `Consolas`，部分中文回退为 `Microsoft YaHei`。字体文件清单单独保存，不能用文件存在性代替实际使用检查。

### 已独立复现的字体状态差异

24 次系统字体冷启动中，**2 次**出现以下差异（DPR 1 与 2 各一次，均 cold=6）：

| 项目                                       | 普通样本                               | 异常样本                          |
| ------------------------------------------ | -------------------------------------- | --------------------------------- |
| 计算字体                                   | `"Cascadia Code", Consolas, monospace` | 相同                              |
| `document.fonts.status`                    | loaded                                 | loaded                            |
| 行号字号/计算行高                          | 12px / 21.6px                          | 相同                              |
| 实际代码字体集合                           | Cascadia Code Regular                  | **Arial + Cascadia Code Regular** |
| `::before` 宽度与 `min-width:3ch` 的解析值 | 21.1px                                 | **20px**                          |
| 代码宽度                                   | 573.6500244140625px                    | **572.5499877929688px**           |
| 代码高度                                   | 3744px                                 | 3744px                            |

代码行本身的字体记录仍为 Cascadia；额外 Arial 出现在整个代码范围中，并伴随生成行号的 `ch` 尺寸变化，指向生成内容/字体度量状态。**这不是确认原高度问题因果链的充分证据。** 首轮 DPR 2 的一次冷启动也出现过相同宽度现象。汇总中的 7 次重复比较不等包含这 3 份异常样本：首轮以异常首样本比较其余 5 份、冷启动追测另外 2 份；不是 7 个新增站点失败，也没有删除异常记录。

### 固定字体的控制结果

只在实验中将同名 CSS 字体绑定到 `C:/Windows/Fonts/CascadiaCode.ttf`，SHA256：

`cfb6a8d474018fe46d53a427e5fbee44b998822d0d3d8772914bd712cfc55ac4`

计算字体名、字号、字重和行高不变。24 次冷启动全部得到相同实际字体、21.1px 行号、573.6500244140625px 代码宽度和 3744px 高度，同 DPR 下所有逐行原始数据精确相等。**这是独立实验的可重复性证据，不是完整站点验收通过证明。** 没有给生产页面添加字体文件或覆盖字体。

### 原失败首次累计偏移

对前轮原始追踪重新计算，而非声称本轮重现：

- 首个代码行 `node -v`，DOM 索引 499：顶部两次均为 `3276.583251953125`；高度从 23.5 变成 `23.400009155273438`。
- 第二行 `npm -v`，DOM 索引 502：顶部首次分离，`3300.083251953125` 对 `3299.9833984375`，约 0.1px。
- 第 160 行顶部相差约 15.9004px；160 个行框差值合计 `16.000015258789062px`；文章容器相差 **16px**。
- 当时首代码行宽度还从 352.3500061035156 变成 355.45001220703125px。旧采集没有实际字体记录，因此不能将这 3.1px 变化直接归因到本轮发现的 Arial 状态。

完整逐行前后数据见 `historical-first-displacement.json`。高度差不能用 `clientHeight` 的整数舍入解释；原始小数矩形本身已经不同。

## 处理建议：保持严格的替代采集契约（尚未接入站点门禁）

1. **环境先验**：固定 Firefox 二进制、操作系统/字体文件哈希、DPR、真实视口及内容 SHA。逐块记录实际字体与生成内容尺寸，不能只等待 `fonts.ready`。字体状态不符立即判为采集环境失败；不自动重试、丢弃冷启动、轮询到好结果或增加超时。
2. **字体控制实验**：在独立参考采集环境中绑定经确认的同一字体文件，并覆盖中文、空行、行号和数学字体回退。先证明完整站点冷/热启动都可重复，再申请建立 Firefox 自身的独立参考。对测试环境的字体绑定需要明确记录，不能假称已验证所有用户系统字体。
3. **分层精确几何**：导航、容器宽度/居中/间距采用固定几何契约；代码逐行、表格和图片采用各自局部坐标的精确契约，同时检查块间间距、后续定位标记与组装后的页面位置。不只比较一个受 160 行累积影响的总高度，也不扣掉任意“已知误差”。0.1px 行高和 1px 位移都必须失败。
4. **门禁保留**：新契约尚是提案和独立样本试验；现有两项继续阻断。完整页面仍有 23.5px 状态时，需要进一步缩减触发条件和检查其实际字体，不能以本轮字体控制结果豁免它。

`strict-geometry.test.mjs` 的 **6/6** 是独立证据和契约试验：重放原始几何、拒绝 0.1px 行高、1px 位移/宽度、缺行及字号变化，拒绝冷启动异常字体，验证固定字体 24 次重复。它不计入或替代原来的 86 项站点测试。

不推荐未经验证的 CSS“修复”：`display:block` 控制会让保留的换行文本形成额外行，代码高度变为 **7464.60009765625px**；直接设置 `line-height:23.4px` 因行号继承及基线组合反而测到 **23.9px** 行框、**3824px** 总高。这两项均仅在实验出现，未应用到产品。只有确认完整页面的真正触发条件后，才评估隔离行号行高/基线的最小调整。

## 复现入口

在项目根目录使用新的输出目录（脚本拒绝覆盖已有目录）：

```powershell
$env:LINEBOX_IFRAME='1'
$env:LINEBOX_DPRS='1,2'
$env:LINEBOX_VARIANTS='original'
$env:LINEBOX_TEXTS='latin'
$env:LINEBOX_COLD='12'
$env:LINEBOX_WIDTHS='320'
$env:LINEBOX_FIXTURE='docs/evidence/linebox-deploy-drill/fixture-9c3e710629f288c4.html'
node scripts/experiments/firefox-linebox.mjs .local-tools/linebox-new-system-run
# 改为 controlled-font，再用另一个新目录，复现固定字体组。
node --test scripts/experiments/strict-geometry.test.mjs
```

默认字体文件路径可用 `LINEBOX_FONT_FILE` 指定，浏览器路径可用 `FIREFOX_EXECUTABLE_PATH` 指定。完整矩阵另见 `linebox-playwright.mjs` 和压缩原始数据。每份 `fixture-*.html` 都按实际执行字节保留哈希，没有以格式化后的新文件冒充旧实验文件。
