# Firefox 字体与 WebKit 转场专项调查（2026-10-18）

本轮只新增诊断脚本、独立实验和证据。没有改网站源码、字体配置、视觉设计、Markdown、URL、SEO、生产配置、正式测试断言或冻结基准。所有浏览器使用自建测试配置；本机 Firefox 155 对照没有连接用户正在使用的配置。没有部署。

## 结论

| 项目    | 已确认                                                                                                                     | 尚未关闭                                                                               |
| ------- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Firefox | 部分原生字体组会选到 Arial，尽管计算字体列表以 Cascadia 开头。实际字形、行号宽度与普通文字对照均证实，属于真实渲染状态差异 | 原历史 23.4/23.5px 高度切换仍未独立复现，不能把它自动归到本轮已定位的字体组异常        |
| WebKit  | 缺少的是入站转场对象：`pageswap` 有对象，而目标 `pagereveal.viewTransition` 为 null；与超过约 4 秒的入站绘制延迟严格对应   | 绘制为何停顿仍未查到平台内部根因；不能据 Windows Playwright 结果宣称真实 Safari 已验证 |

**两项 Firefox 几何验收及 WebKit 间歇风险继续保留，不放宽阈值、不忽略失败，也不宣称验收全绿。**

## 一、Firefox：实际字体组而非 CSS 候选列表

### 1. 新增证据

使用 Firefox 的匿名内容检查与字体 Range 定位，直接读取 `_moz_generated_content_before` 内的数字 `1`：

| 同一份文档的部分           | 计算字体                               | 异常进程中的实际字体  |
| -------------------------- | -------------------------------------- | --------------------- |
| 13px 代码文字              | `"Cascadia Code", Consolas, monospace` | Cascadia Code Regular |
| 12px 行号数字              | 相同列表                               | **Arial**             |
| 新建的 12px 普通 span 对照 | 相同列表                               | **Arial**             |

字体记录为 `fromFontGroup: true`、`fromSystemFallback: false`；匿名 Range 明确指向行号数字。普通 span 同样复现，因此不能简单认定是 `counter()` 或伪元素专属错误，也不是 Inspector 把其他文字误算进来。

异常时 `3ch` 解析成 **20px**；正常为 **21.1px**。Canvas 分别测得 Arial 的零字符宽约 6.6667px、Cascadia 约 7.0333px，与三倍 `ch` 结果吻合。CSS 计算值“看起来正确”不代表实际字形正确。读取依据见 [Mozilla InspectorUtils 定义](https://raw.githubusercontent.com/mozilla/gecko-dev/master/dom/chrome-webidl/InspectorUtils.webidl)。

### 2. 对照结果

| 实验                                 | 冷启动数 | 初始字体不匹配次数 |
| ------------------------------------ | -------: | -----------------: |
| 首轮最小样本与完整文章路径           |       12 |                  0 |
| 匿名内容/Range 定位                  |       24 |                  4 |
| 字体列表、字面量行号和普通 span 对照 |       24 |                  5 |
| 关闭共享字体列表                     |       12 |                  1 |
| 本机 Firefox 155，独立空白配置       |       12 |                  2 |
| Times 行号补充对照                   |        1 |                  1 |
| 16 种文字/行号字体组合               |        1 |                  0 |

主运行时为隔离 Playwright Firefox 157.0；另一个对照是用户机器现有 Firefox 155.0 程序的新配置，不能将其视作已认证的 Mozilla 干净发行包。版本不同，也不能据此单独判断是哪个版本回归。

在发生异常的同一文档内：

- 再读取 Canvas、将 `3ch` 改写为同值 `calc(3ch + 0px)`，都不修复异常。
- 把 `counter(line)` 改为字面量 `"1"`，仍使用 Arial。
- 单独指定 Cascadia、移除 generic 或改变部分字体样式键时，可重新得到 Cascadia。
- 本机 155 的两个异常进程在恢复**原字体列表和原 kerning**后，再次回到 Arial。

这些证据指向**原生字体列表匹配/字体组状态或缓存**，而非主题规则覆盖或单纯“还没等两帧”。关闭 `gfx.e10s.font-list.shared` 没有消除问题，不应把这个偏好开关当作已证明的修复。它只是实验配置，正式测试与用户配置未修改。

尚未定位到 Gecko/Windows 内部的具体代码缺陷；不将未查证的上游问题编号宣称为本项目根因。

### 3. 与原 0.1px 问题的关系

36 份完整文章观测中，320px 行框为约 23.4px，820px 为约 25.2px，没有再次出现 23.5px。16 种文字/行号字体组合也没有产生该高度切换。Times New Roman 可以令 `3ch` 变成 18px，仍不足以重现原高度差。

因此，**原来累计 16px 的高度变化尚不能用“Arial 行号”直接解释**。原始追踪缺少当时的实际字体信息，不能补写猜测。此前提出的显式字体文件控制可用于验证采集环境，但不能据此豁免真实用户的原生字体风险。

建议保留网站视觉与现有门禁。下一步若继续追原高度，应在相同顶层导航/窗口路径中同时记录每个代码行及匿名行号字体、局部矩形、字体组状态；现有 `firefox-font-cause.mjs` 已具备所需读取能力。不要仅凭 `document.fonts.ready` 或增加等待时间收集“好样本”。

首批匿名节点调用少传了一个参数，记录中保留错误，未用于匿名字形结论；后续改用官方三参数签名。另有一次浏览器在启动上限后才开始监听，未建立会话；失败日志保留，未把它算作有效字体观测。

## 二、WebKit：入站对象在绘制超时后缺失

### 1. 排除“事件丢了”与“连续点击没等动画”

诊断将同步的 `pagereveal`、`pageswap` 与后续 `ready`/`finished` 分开记录，同时保留浏览器内时间线及进程侧记录。

117 个可对照的导航跳转：

- 出站 `pageswap.viewTransition` 全部为真。
- 源页面均已 reveal，未发现点击时上一场动画尚未完成的样本。
- 39 次入站对象为 null，不是 `ready` 回调遗漏，也不是增加 Node 侧等待就会补出对象。
- 缺少对象的 `pageswap → pagereveal` 间隔最小 **4019ms**，最大 **25111ms**；有对象的最长间隔为 **3918ms**。

这一分界与 [WebKit 的 4 秒默认期限](https://raw.githubusercontent.com/WebKit/WebKit/main/Source/WebCore/dom/ViewTransition.h)及[入站对象解析中的时间检查](https://raw.githubusercontent.com/WebKit/WebKit/main/Source/WebCore/dom/ViewTransition.cpp)吻合。这里引用的是上游源码，不是对本地二进制堆栈的逆向证明；本地行为提供了相符的强证据。

可以确认的直接原因是：**目标文档第一次可 reveal 的时间过晚，浏览器没有提供入站转场对象。** 更早发生的绘制停顿究竟来自平台图形、引擎调度或测试宿主内部，尚未定位。

### 2. 对照实验

以下为调查探针，表中“达到 3”仅表示三段导航的原生事件计数达到预期，不等价于原站点测试或全部功能通过。

| 完整站点探针                      | 运行次数 | 达到 3 / 未达到 3 |
| --------------------------------- | -------: | ----------------- |
| 旧观察器及详细时间线              |       24 | 8 / 16            |
| 首次网络计时                      |        3 | 3 / 0             |
| 网络计时重复                      |       12 | 1 / 11            |
| 禁用外部增强脚本                  |        4 | 0 / 4             |
| Storage / matchMedia 计时         |        6 | 2 / 4             |
| 原 HTML 与内联同一 CSS 的交替对照 |        8 | 3 / 5             |

其中 Storage getter、getItem、setItem 及 matchMedia 实测耗时为 **0–1ms**，没有解释秒级停顿；禁用增强脚本仍失败。资源响应很快，部分失败的长间隔发生在资源到达与文档可绘制之间。不要据此去改外观切换、搜索、目录或文章脚本。

独立最小页面只保留标题、链接、现有 Motion CSS 和相同的三段导航，完全没有 Autuswing 组件或业务脚本：

| 最小页面                     | 运行次数 | 三段都产生转场 / 至少一段缺失 |
| ---------------------------- | -------: | ----------------------------- |
| 内联 CSS                     |       12 | 12 / 0                        |
| 外部同一 CSS                 |       12 | 8 / 4                         |
| 外部 CSS，去掉 Node 事件桥接 |       12 | 11 / 1                        |

无桥接失败样本收到了三次目标 `pagereveal`，三次对象都为 null，最终仍到达 `/3/`。因此不能归因于回调桥接丢包。复用浏览器与新浏览器两类均记录在原始数据中，不把一次新进程通过当作修复。

完整站点内联 CSS 的 4 次对照中仍有 3 次失败，**简单内联样式不是已证明的解决方案**。独立页面的内联/外部差别只是进一步缩减触发条件的线索，不能据此随意改变 Astro 的样式输出策略。

### 3. 串行隔离确认

探索阶段有独立浏览器进程并行运行，各批次失败率不能直接当作真实用户故障率。最后停止其他本轮浏览器后，单独执行：

- **原有 WebKit 用例 3/3 通过**，每次约 13 秒，总计 44.4 秒；单 worker、零重试、原 30 秒上限和全部原断言未改。
- 外部 CSS、无 Node 桥接的最小页面，复用进程 3 次与新建进程 3 次，**6/6** 均收到三次转场。

隔离后这两组通过，说明并发/平台调度值得继续控制；尚未做足以证明所有原始失败均由并发导致的受控压力 A/B，也不能用这九次通过关闭此前真实的空转场。当前结论应区分“正常隔离复测通过”与“已找到全部绘制停顿根因”。

### 4. 验收处理

目前定位到**本机 Windows Playwright WebKit 的跨文档绘制路径**，不需要用重新设计或禁用动画掩盖。正常导航仍要求原有三次转场、分组、320/120ms 和 14px 断言；本轮未修改它们。

等待更久不会让已经为 null 的事件变成动画。不要把断言改成“至少两次”或对失败重试取绿。后续应使用此独立复现对照真实 macOS Safari/其他 WebKit 平台，或采集 Windows 端原生渲染/IPC 追踪；真实 Safari 在本环境尚未验证。浏览器允许超时退化并不等于正常场景的性能验收已经关闭。
